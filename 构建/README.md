# 本地构建说明

此目录包含本地插件构建器及其 ESM 静态打包器。构建结果用于开发和隔离验证；它不是完整平台容器，也不构成 Figma 官方发行或公开许可证授权。

## 命令与输出

```bash
# 默认仅生成开发清单：占位插件 ID、无网络域名
npm run build

# 生成单独的开发源码包；仍不是公开发行
node 构建/build.mjs --release

# C34 自建 HTTPS 模式的构建能力需显式选择；不要在本地准备阶段生成或分发正式插件包
node 构建/build.mjs --production-compat --service-mode custom-https --plugin-id <已核验的数字插件ID>
```

默认开发构建使用占位身份并禁用网络。生产兼容构建必须明确选定插件身份与模式；固定 HTTPS 服务模式还必须提供精确的 `--service-origin`。`custom-https` 模式不写入默认服务地址，由用户在插件中选择服务。即使构建成功，也不证明插件已获 Figma 登记、域名/权限已获批准、商标权属已清障或许可已生效。

开发与发布构建分别写入 `开发包/`、`构建产物/`。这些输出是本机生成文件，可能带占位 ID、示例域名或过时设置，**不得直接上传到 GitHub、Docker Hub 或 Figma**。在发布前应从核准的 C34 源码重新生成到空白输出目录，核验 manifest、权限、文件哈希、第三方材料和对应源码，并完成法律与平台审查。

## 依赖与原生编码器

本构建器使用 Node.js 标准库，不需要 npm 运行时依赖。合成演示宿主的 JPEG 预览还可能调用外部 `vips`；该工具未随项目打包，也不是完整平台镜像的一部分。平台原生编码器使用独立构建脚本和锁定依赖；要求本机具备 `dpkg-deb` 与兼容 C 编译器，相关二进制不得作为源码发行文件提交。

## 文件边界

构建器只允许读取明确列出的源码文件，拒绝目录递归、符号链接与敏感路径；输出写入本项目内部并设置私有权限。发布前的正式发布包应由独立且可复现的清洁打包流程生成，不要把 `开发包/` 或 `构建产物/` 当作源代码或正式发行物。
