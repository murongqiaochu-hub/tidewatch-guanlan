# 快速测试步骤（隔离候选版）

更新：2026-11-06。只用于 C34 源码副本的本机或内网测试；不要连接现有服务、生产数据或生产凭据。

## 1. 环境与目录

需要 Node.js 22 或更新版本，并为数据、密钥和输出准备独立测试路径。不要在原生产目录内解压、构建或启动。

```bash
cd <C34候选源码目录>
node 部署与运维/脚本/环境检查.mjs --data-dir /abs/path/tidewatch-test-data --port 4318
```

只有检查结果明确通过后继续。不要使用包含真实数据或凭据的目录。

## 2. 本地启动

```bash
export HANDOFF_DATA_DIR=/abs/path/tidewatch-test-data
export HANDOFF_JWT_SECRET_FILE=/abs/path/tidewatch-test-secrets/jwt
export HANDOFF_ADMIN_PASSWORD_FILE=/abs/path/tidewatch-test-secrets/admin-password
export HANDOFF_HOST=127.0.0.1 HANDOFF_PORT=4318
npm start
```

在另一个终端验证：

```bash
curl -fsS http://127.0.0.1:4318/api/health
```

引导密码文件只用于全新测试目录。已有目录不会重置管理员。密钥文件与目录应为当前用户私有；不要把秘密贴入日志、命令历史或仓库。

## 3. 合成数据基础检查

1. 在浏览器打开本机 `/login`，使用专用测试账号登录。
2. 创建一个仅含虚构内容的测试项目和分组，检查刷新、退出及本地重启后的数据行为。
3. 记录实际页面、浏览器控制台和服务日志结果；不要导入客户设计或个人信息。

## 4. 插件与设备测试

C34 插件使用用户指定的 HTTPS 服务地址，不应把发布者地址或示例域名写成默认值。任何插件包均须从确认过的 C34 源码和清单显式构建；`构建产物/` 中现存的占位或兼容文件不是可导入的正式包。不要更换既有插件 ID、协议/存储标识或网络权限策略。

真实 Figma/macOS 导入与上传仍需在用户设备单独验收；浏览器模型测试不能代替实机结果。

## 5. 边界

- 不执行生产部署、数据迁移、Docker/Compose 启动或公开上传。
- 本副本没有完整服务容器配置；原生编码器 Dockerfile 不等于平台镜像。
- 全量自动化测试、容器复现和正式许可证尚未通过发布门槛。
