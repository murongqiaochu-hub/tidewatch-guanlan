# 01 安装与初始化（开发候选版）

本流程只用于**本机或内网测试**。不要指向生产数据目录，不要在生产容器内执行。

## 1. 依赖检查

要求：Linux x86_64 + glibc，Node.js ≥ 22；建议具备 `curl`、`tar`、`gzip`、`sha256sum`。原生预览需要候选包内的 `原生编码器`（若使用源码包，需先构建，见 §5）。

先跑只读检查：

```bash
node 部署与运维/脚本/环境检查.mjs --data-dir /abs/own/test-data --port 4318
```

输出 JSON 会列出 Node 版本、命令是否存在、目录是否可写、端口是否占用、密钥文件权限等；不读取也不打印任何密钥内容。

## 2. 准备目录与密钥

```bash
export HANDOFF_DATA_DIR=/abs/own/test-data
export HANDOFF_JWT_SECRET_FILE=/abs/own/test-secrets/jwt
export HANDOFF_ADMIN_PASSWORD_FILE=/abs/own/test-secrets/admin
mkdir -p "$HANDOFF_DATA_DIR" "$(dirname "$HANDOFF_JWT_SECRET_FILE")"
chmod 700 "$HANDOFF_DATA_DIR" "$(dirname "$HANDOFF_JWT_SECRET_FILE")"
head -c 48 /dev/urandom | base64 | tr -d '\n' > "$HANDOFF_JWT_SECRET_FILE"
head -c 24 /dev/urandom | base64 | tr -d '\n' > "$HANDOFF_ADMIN_PASSWORD_FILE"
chmod 600 "$HANDOFF_JWT_SECRET_FILE" "$HANDOFF_ADMIN_PASSWORD_FILE"
```

要求：数据目录必须为空或不存在；两个密钥必须是普通文件、权限不高于 0600；路径必须是绝对路径。

## 3. 启动

```bash
export HANDOFF_HOST=127.0.0.1 HANDOFF_PORT=4318
node 平台/启动.mjs
```

成功时输出一行 JSON：`{"status":"listening",...}`。首次启动会创建管理员 `admin`，密码取自 `HANDOFF_ADMIN_PASSWORD_FILE`；**已有数据目录不会重置账号**。

## 4. 验证

另开终端：

```bash
curl -fsS http://127.0.0.1:4318/api/health
curl -fsS -o /dev/null -w '%{http_code}\n' http://127.0.0.1:4318/login
```

预期：健康检查返回 `{"status":"ok",...}`；登录页 200。浏览器打开 `http://127.0.0.1:4318/login`，用 `admin` 与初始密码登录，创建测试项目。

## 5. 原生编码器（只有源码包时需要）

候选包若不含 `原生编码器/运行时/`，可在包内构建：

```bash
node 原生编码器/build.mjs
```

需要 `cc`、`dpkg-deb` 与包内 `依赖包/`、`第三方源码/`。构建输出 `heron-codec`，启动时通过 `HANDOFF_CODEC_BINARY` 指向它；未配置时预览返回 503，不影响其他功能。

## 6. 常见失败与处理

| 现象 | 原因 | 处理 |
|---|---|---|
| 启动立即退出，提示配置失败 | 数据目录/密钥缺失或权限不对 | 跑环境检查；确认绝对路径、0600/0700 |
| 健康检查失败 | 端口未监听/被占用/主机绑定错误 | 换端口；确认 `HANDOFF_HOST` |
| 登录 401 | 密码不对或账号被禁用 | 用初始密码文件；已有数据不会重置 |
| 预览 503 | 未配置编码器 | 构建并设置 `HANDOFF_CODEC_BINARY` |
| 网页能开但插件连不上 | 插件用 HTTPS 地址，本机是 HTTP | 插件测试需 HTTPS 或使用现有 HTTPS 服务；本候选不提供 TLS |

> 服务启动失败时只输出通用错误，不打印路径/密钥；具体原因用环境检查与上表逐项核对。

## 7. 停止

前台运行时 `Ctrl+C`；后台运行时向进程发送 `SIGTERM`，等待退出后再做备份。
