## 1. 产物

| 文件 | 用途 |
|---|---|
| `Dockerfile` | 平台服务镜像；只含 `平台/`、`查看器/`、`界面/` 与两个宿主静态文件 |
| `.dockerignore` | 排除测试、审计、来源记录、品牌素材与本机产物 |
| `compose.yaml` | 单服务编排：非 root、只监听回环、资源上限、数据卷、密钥绑定挂载 |
| `.env.example` | 需要填写的公开来源 |
| `secrets/README.md` | 密钥文件生成与权限要求 |
| `部署与运维/反代/Caddyfile`、`nginx.conf.example` | HTTPS 反向代理样例 |

原生图片编码器不在镜像内：需要预览能力时，另外构建 `原生编码器` 产物并挂载，或用 `HANDOFF_CODEC_BINARY` 指向它；未配置时预览接口返回 503，其他功能不受影响。插件下载同理：镜像不含 `downloads/plugin.zip`，需要把自建 HTTPS 模式的插件包构造成绝对路径并用 `HANDOFF_PLUGIN_ARCHIVE` 指向；未配置时下载请求会失败，不会返回伪造包。

## 2. 前置条件

- Docker Engine 24+ 与 Compose v2。
- 一个域名与可签发的 TLS 证书（Caddy 可自动申请）。
- 与运行用户匹配的密钥目录权限：容器内运行身份是 `10001:10001`。

## 3. 配置

```bash
cp .env.example .env
# 编辑 .env，写入精确 HTTPS 来源，例如 https://tidewatch.example.com

mkdir -p secrets && chmod 700 secrets
head -c 48 /dev/urandom | base64 | tr -d '\n' > secrets/jwt
head -c 24 /dev/urandom | base64 | tr -d '\n' > secrets/admin-password
chown 10001:10001 secrets/jwt secrets/admin-password
chmod 600 secrets/jwt secrets/admin-password
```

`HANDOFF_PUBLIC_ORIGIN` 必须是精确 origin：协议 + 主机（带端口时含端口），不能有路径或结尾斜杠。反代终止 TLS 时 `HANDOFF_ORIGIN_MODE` 保持 `fixed`；服务端不读取 `X-Forwarded-Proto`，安全性来自该精确来源与请求的 `Origin` 比对。

## 4. 构建与启动

```bash
docker compose build
docker compose up -d
docker compose ps
docker compose logs --tail=50 platform
```

首次启动会用 `secrets/admin-password` 初始化管理员 `admin`；数据卷里已有 `catalog.json` 后不会重置账号。

## 5. 验证

```bash
curl -fsS http://127.0.0.1:4318/api/health
curl -fsS -o /dev/null -w '%{http_code}\n' http://127.0.0.1:4318/login
```

预期健康检查返回 `{"status":"ok",...}`，`/login` 返回 200。容器健康状态应为 `healthy`（镜像内置 `HEALTHCHECK`）。

## 6. 反向代理

把 `部署与运维/反代/` 中的样例改成自己的域名后放到代理主机上：

- Caddy：`caddy run --config Caddyfile`，或在 Caddyfile 中 `import` 该站点块。
- nginx：把 `nginx.conf.example` 放进 `conf.d/`，替换证书路径后 `nginx -t && nginx -s reload`。

代理必须保留原始 `Host` 与 `Origin`；不要覆盖 `Origin` 为固定值，也不要放宽到通配 CORS 来"绕开"来源校验。

## 7. 插件连接

插件不内置服务地址。安装后在插件中选择 `custom-https` 并填写同一条 HTTPS 地址（协议、主机、端口要与 `HANDOFF_PUBLIC_ORIGIN` 完全一致）。凭据按 origin 隔离，切服务不迁移登录状态。

## 8. 备份、升级与回退

```bash
# 备份数据卷（使用已构建的镜像，避免依赖额外拉取）
docker run --rm -v tidewatch-guanlan_tidewatch-data:/data:ro \
  -v "$PWD/backups":/backup tidewatch-guanlan:local \
  tar czf /backup/data-$(date +%Y%m%d-%H%M%S).tgz -C /data .

# 升级：改代码后重建并滚动重启
docker compose build && docker compose up -d

# 回退：切回上一个镜像 tag，或恢复备份到新卷
docker compose down
docker volume create tidewatch-data-restore
docker run --rm -v tidewatch-data-restore:/target \
  -v "$PWD/backups":/backup tidewatch-guanlan:local \
  tar xzf /backup/data-<时间戳>.tgz -C /target
```

不要用旧版本覆盖已有数据卷后继续写；回退前先停写并保留当前数据副本。

## 9. 安全与资源边界

- 容器以非 root（`10001:10001`）运行，`cap_drop: ALL`，`no-new-privileges`。
- 端口只绑 `127.0.0.1`，由同机反代对外；如需跨机访问，改成内网地址并确保有防火墙。
- 资源上限示例为 1 CPU / 512 MiB，真实取值需按实际负载压测后调整。
- 数据卷与密钥分离存放；密钥不要打进镜像或提交到仓库。
