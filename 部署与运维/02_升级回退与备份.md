# 02 升级、回退与备份恢复（开发候选版）

仅用于自有测试环境；不要对生产目录执行。所有代码块使用 Bash。先核对绝对路径、停服并等待退出，再备份；不能只发SIGTERM就开始复制。

## 1. 地址配置与升级

- `HANDOFF_PUBLIC_ORIGIN`：对外HTTPS地址，插件校验与Cookie使用。
- `HANDOFF_LEGACY_LAN_ORIGINS`：明确保留的旧HTTP内网地址，逗号分隔；未配置不会自动迁移旧地址。
- 保留旧代码、新代码与当前数据目录，分别解压到新目录，禁止覆盖工作中的应用或数据。

```bash
cd <新候选目录>/源码
export HANDOFF_DATA_DIR=/abs/own/test-data
export HANDOFF_JWT_SECRET_FILE=/abs/own/test-secrets/jwt
export HANDOFF_ADMIN_PASSWORD_FILE=/abs/own/test-secrets/admin
export HANDOFF_PUBLIC_ORIGIN=https://<你的测试地址>
# 可选：export HANDOFF_LEGACY_LAN_ORIGINS=http://<旧别名>:4318
node 平台/启动.mjs
```

新插件要用真实测试地址重建；候选插件占位地址不能登录。旧代码必须保留，但“保留旧代码”不等于允许旧代码可写打开新数据。

## 2. 停服备份（任何一步失败都不得标记成功）

先人工确认服务已经退出、目录确为自有测试数据；备份根目录必须在数据目录外。下例不删除任何旧备份，失败目录保留现场。备份记录真实文件mtime和权限，不套用源码归档的固定时间/owner策略。

```bash
set -euo pipefail
umask 077
: "${HANDOFF_DATA_DIR:?必须设置自有测试数据目录}"
DATA=$(realpath -e -- "$HANDOFF_DATA_DIR")
test "$DATA" != / && test -d "$DATA" && test -f "$DATA/catalog.json"
BACKUP_ROOT=/abs/own/test-backups
mkdir -p -- "$BACKUP_ROOT"
BACKUP_ROOT=$(realpath -e -- "$BACKUP_ROOT")
case "$BACKUP_ROOT/" in "$DATA/"*) echo '备份目录不能在数据内' >&2; exit 1;; esac
BACKUP=$(mktemp -d "$BACKUP_ROOT/tidewatch-test-$(date +%Y%m%d-%H%M%S)-XXXXXX")
chmod 700 -- "$BACKUP"
# pipefail确保tar失败不能被gzip成功掩盖；临时文件不作为可恢复备份。
tar -C "$DATA" -cf - . | gzip -n > "$BACKUP/data.tar.gz.partial"
tar -tzf "$BACKUP/data.tar.gz.partial" > "$BACKUP/成员清单.txt"
mv -- "$BACKUP/data.tar.gz.partial" "$BACKUP/data.tar.gz"
# 相对路径保证搬到其他磁盘后仍验证当前归档，而非原目录旧副本。
(cd "$BACKUP" && sha256sum data.tar.gz > data.tar.gz.sha256 && sha256sum -c data.tar.gz.sha256)
printf '%s\n' "$BACKUP"
```

本流程假定数据仅包含项目允许的普通文件和目录、不含外部符号链接、设备文件或跨目录硬链接；发现这些类型应停止并明确恢复策略，而不是跟随外部目标。tar保留普通权限和mtime；非root恢复不会恢复原owner，ACL/xattr未覆盖。若业务依赖这些元数据，必须另做明确记录和专项恢复验收，不称“全元数据备份”。

归档SHA只证明归档字节未变，不证明资源业务一致。备份后还需记录账号/项目/画板/修订/资产数量、catalog摘要、原图逐文件SHA并核对catalog引用，保留独立验收证据。上述命令不包含这项业务验收，完成前不要删除源数据或声明备份恢复完整。

## 3. 恢复到新目录（不会覆盖当前数据）

仅接受自己创建、来源可信、路径和类型已经检查过的归档；SHA不是签名，不能令不可信归档安全。先停服务、确认目标不存在。新目录校验完成前，原数据目录不得删除/覆盖/改写。

```bash
set -euo pipefail
umask 077
BACKUP=/abs/own/test-backups/<已核验的备份目录>
BACKUP=$(realpath -e -- "$BACKUP")
# 固定只允许校验清单中一个相对文件名，拒绝绝对路径/../等错对象。
test "$(wc -l < "$BACKUP/data.tar.gz.sha256")" -eq 1
(cd "$BACKUP" && LC_ALL=C grep -Eq '^[0-9a-f]{64}  data[.]tar[.]gz$' data.tar.gz.sha256 && sha256sum -c data.tar.gz.sha256)
# 校验失败已退出，不会创建恢复目录或解包。
RESTORE=/abs/own/test-restore-data
if test -e "$RESTORE" || test -L "$RESTORE"; then echo '恢复目标已存在' >&2; exit 1; fi
mkdir -m 700 -- "$RESTORE"
# 服务始终停止；解包失败时目录属于失败现场，不得直接启用。
tar --keep-old-files --no-same-owner -xzf "$BACKUP/data.tar.gz" -C "$RESTORE"
test -f "$RESTORE/catalog.json" && test -d "$RESTORE/assets"
# 后续先做离线业务/资源完整性核对，再在隔离副本启动验证，最后人工切换。
```

不要对未知链接执行`chmod -R`。恢复所用运行用户需要读写自己数据，权限不匹配时先查明owner/mode并在隔离副本中处理，不对现用目录广泛放权。

## 4. 应用回退与灾难恢复是两件事

- **应用回退不得回灌升级前备份覆盖当前数据。** 升级后任何新写入发生后，恢复旧备份必然丢掉这些新写入；这不是正常回退。
- 必须保留当前全部数据、失败目录与日志，先停止写入。只有经独立验证能读取当前完整schema（含未知字段、修订、资产和权限）的兼容旧代码，才可在数据真正只读的隔离副本/只读挂载下提供应急读取。
- 当前平台没有已确认可用的只读恢复开关；不要把其他服务版本的环境变量、旧数据只读开关或回退方式直接套用，也不能把“旧代码读到新项目列表”当作兼容可写证明。
- 未有兼容只读候选时保持写服务停止，走前向修复；不要直接启动原旧版本可写接入新数据。
- 灾难恢复需要独立、明确的恢复点与可接受数据损失确认；先恢复到新目录并验收，不覆盖现用数据。本文没有授权对生产做灾难恢复。

## 5. 验证清单与已知空缺

- health、登录、账号/项目数量、画板/历史修订、资源逐SHA及引用一致。
- 打开真实画板与切图；编码器未配置时允许明确503，不冒预览成功。
- 插件下载/校验通过（显式PUBLIC_ORIGIN）。
- 必须测试备份tar失败、gzip失败、SHA错误、磁盘满、恢复中断：均应失败关闭且旧数据可用。
- Docker/Compose、HTTPS/TLS、反代、真实Figma/Mac、24k/8k和生产迁移仍未验收。
- 本地演练用fs.cp和项目列表，不代表本文tar/SHA故障路径或全量业务数据已验证。
